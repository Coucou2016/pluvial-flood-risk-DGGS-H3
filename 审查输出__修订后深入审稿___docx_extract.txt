P0-01　尺度损失 Jaccard 的预算定义、表、图和正文相互冲突
发现与证据。rollups.py:397–420 以 k=round(0.10×1857)=186 生成分数边界的 fractional weights，但 262 个 R10 单元都在最高分 1 上并列，因此所谓 hard hotspot 实际包含 262 个单元而不是 186 个。代码把这些权重按父单元相加后截断到 1，并直接令 target_parent_area=fine_hot_area=2.813 km²；这不是细热点父单元支撑面积。实际 hard parent support 在 R9 为 139 个父单元、约 14.714 km²，在 R8 为 38 个父单元、约 28.157 km²。随后 coarse_k 又通过“先按面积累计、再把并列项全部加入、再按 cell count 做一次 top-k”得到，预算含义再次变化。最大值聚合 hard Jaccard=1.0 主要是并列与 presence 保留的定义结果。与此同时，Figure 6 使用 figures.py:708–737 的另一套“各分辨率独立 exact top-k + H3 索引破并列”方法。当前图上矩阵实际为 R10–R9 0.216、R10–R8 0.132、R9–R8 0.294；正文 4.3 写 0.180/0.111，图注写 0.105/0.111，Table 4 写 hard 0.105/soft 0.111。
为什么重要。尺度损失是论文的核心贡献之一。当前协议不能支持“projected-parent-area matched”或“Figure 6 reproduces Table 4”，会被审稿人视为定义漂移和结果选择。
具体修改。推荐把细热点定义为面积加权的 fractional membership。对每个粗父单元 p 定义 w_ref(p)=Σ_i∈p a_i w_i / Σ_i∈p a_i；粗尺度按分数排序，允许边界单元/并列组分数化，使选中粗面积严格等于目标预算。主指标用 area-weighted soft Jaccard：Σ a_p min(w_ref,w_coarse)/Σ a_p max(w_ref,w_coarse)。hard Jaccard 只作为敏感性：对并列单元做固定种子的重复随机分配（建议 1000 次），报告中位数和 95% 区间。Figure 6 必须直接读取 Table 4 的同一张长表，或调用同一个公共函数；删掉 figures.py 内独立的热点选择实现。若不愿重构，应暂时删除 Jaccard headline，仅保留“均值聚合压缩分布”的描述性结果。
验收标准。新增测试必须同时断言：Σw_fine=k；细/粗面积预算误差小于预设容差；图矩阵数值逐项等于 CSV；正文 claim registry 与 CSV 一致；并列情况下 hard 支撑规模不得被表述为 k。重新生成 Table 4、Figures 5–6、Figure S1、README、report.md、audit.md 后，全仓库搜索不得残留 0.180、0.132、过时 0.111 或“exact top-k/H3 tie-break”冲突措辞。
当前 Figure 6。矩阵显示 0.216 / 0.132 / 0.294，与正文、图注和 Table 4 的方法及数值不一致。
P0-02　311 来源不是可审计的官方原始记录，回退查询也不等价
发现与证据。当前 _311_CANDIDATES 优先使用 arcgis_streetfloodtime，其次使用 GitHub CDN，最后才请求 NYC SODA。Lower 文件含 488 条、扩展文件含 1134 条，字段中出现 WPCP、COMB_OR_SE、Outfall、Interceptor 等二次加工属性，ArcGIS owner 为 jeichen_GIS；它更像公开研究/教学派生层，而非官方 NYC 311 原始导出。中央清单也明确 official_identity_verified=false。SODA 回退则仍指向现已表示 2020–present 的 erm2-nwe9，而论文使用的是 2010–2014；其过滤条件还把所有 complaint_type LIKE '%Sewer%' 纳入，仅设 limit=5000，没有日期条件、排序、分页和 unique_key 去重。
为什么重要。311 是标签正类的主要来源（Lower 141/165 个 composite 正类含 311；扩展 367/454）。来源或筛选规则稍有变化就会显著改变标签、模型和地图。当前只能称“公开派生 311 图层”，不能称“按可复现官方规则提取的 NYC 311 街道积水记录”。
具体修改。首选重做：对 2010–2014 使用 NYC Open Data 历史数据集 76ig-c548，而不是 erm2-nwe9；先验写死 agency、complaint_type、descriptor、created_date、bbox 规则，按 unique_key 排序并用 $offset 分页直到空页，去重后冻结完整 URL/查询 JSON、响应元数据、提取日期、行数和 SHA-256。把官方数据设为第一候选，镜像只能作为经过逐行核验的缓存。若保留现有镜像，正文必须改名为“public derived street-flooding complaint layer (2010–2014 snapshot)”，给出创建者、生成脚本/许可和与官方记录的抽样或全量核验。
验收标准。给定冻结查询，从空目录运行两次得到相同行数、unique_key 集合和哈希；无 5000 行截断；所有记录满足日期/空间/类别条件；生成纳入/排除流程表；重新装配后，所有主表、消融、地图和模型均重新计算。
P0-03　真实性链条尚未形成不可变的 run bundle
发现与证据。中央 data/raw/data_manifest.json 的 10 个 Lower 文件哈希均匹配，但不覆盖 data/raw/nyc_expanded。清单字段 retrieved_utc=2026-08-30，实际 DOWNLOAD_MANIFEST 显示 Lower/expanded 下载发生在 8 月 15/17 日，当前字段更像“清单生成时间”。deployment manifest 只有 role、fit_rows、H3 ID 哈希、seed 和特征数，没有配置哈希、特征值/处理表哈希、原始输入哈希和模型文件哈希。工作区审查时有 90 个变更/未跟踪路径，当前结果不对应一个干净 commit/tag。requirements.txt 除 h3 外多为下限，无法锁定 Python 3.13.12、scikit-learn 1.8.0、pandas 3.0.3、NumPy 2.4.6 等实际环境。
为什么重要。现有证据足以说明“当前本机文件能够重建”，却不足以让第三方确定“论文 PDF 对应的唯一代码、数据和环境”。这正是数据真实与可追溯性的最后一公里。
具体修改。为每次正式运行建立 runs/<run_id>/：保存 git commit、dirty flag、完整命令、stdout/stderr、配置副本及哈希、所有 raw manifest 及哈希、processed parquet 哈希、特征名/顺序、target 定义、每折 train/test H3 哈希、OOF 哈希、模型哈希、表图哈希、Python 和依赖锁文件。Lower 与 expanded 各自建立原始清单；把 retrieved_utc 拆为 source_retrieved_utc 与 manifest_generated_utc。停止在 models 根目录保留角色不明的重复模型，或至少用 role.json 强制加载。最终从干净 commit 一键生成论文所用结果并打 tag。
验收标准。一个全新目录或容器中，仅凭仓库、锁文件和公开下载步骤可生成相同输入哈希、处理表哈希、OOF 指标与图表；run_manifest 能从每个论文数字追溯到数据、代码、配置和模型；git status 干净；提交 DOI/Zenodo release 与论文 Data/Code availability 一致。
P0-04　当前测试套件未通过，软件不能宣称完整
发现与证据。实际运行 pytest -q 得到 63 passed、3 failed、1 skipped。失败为 tests/test_negative_control.py::test_negative_control_separates_coastal_and_pluvial、test_assemble_label_scale_table_fast、test_attach_coastal_overlay_does_not_change_labels。生产代码已改为 fallback_synthetic=False 的 fail-closed 行为，而这三个测试仍构造缺 DEM/slope/flow/impervious 等文件的局部 fixture 且未显式允许合成回退，因此抛出 AssemblyError。compileall 通过；git diff --check 因 docs/paper/report.md 多处行尾空白失败。
为什么重要。这是一个可解释的测试回归，不等同于科学结果错误；但测试红灯意味着当前提交不能作为“完整可运行代码”交付，也掩盖了未来真正的回归。
具体修改。测试只验证几何/标签行为时，显式传 fallback_synthetic=True 并在测试名/注释中标明 fixture-only；另加生产路径测试，断言缺任一必需观测层时必定失败。对三个失败测试逐个修复，不要放宽生产默认。清除行尾空白，并在 CI 中固定执行 pytest、compileall、git diff --check 及最小端到端 smoke。
验收标准。干净环境中 pytest 全绿且无 xfail 掩盖；生产 fail-closed 测试存在；git diff --check 无输出；CI 记录保存到正式 run bundle。
P0-05　FloodNet“尚无可用数据”的陈述已过时
发现与证据。代码仍把 https://api.floodnet.nyc/status 当 placeholder probe，正文多处写“no usable FloodNet observations”或“when a suitable sensor layer becomes available”。截至本次审查，NYC Open Data 已公开 FloodNet: Street Flooding Events Measured by FloodNet Sensors（aq7i-eu5q），2026-03-03 对外发布，当前含经过 FloodNet 团队质控的传感器洪水事件，并有独立的传感器位置元数据。
为什么重要。这不是一般性的未来工作措辞错误，而是可核验的事实过时。对一篇强调开放数据与外部验证的论文，忽略已经存在的官方观测数据会削弱可信度。
具体修改。优先把 FloodNet 作为严格独立验证，不参与训练标签：按传感器位置映射 H3，按事件时间/最大水深定义预注册的验证结局，并区分 tidally influenced 传感器；报告传感器数、事件数、覆盖范围、阈值敏感性和按传感器聚类的不确定区间。若时间不足，至少改为“dataset became public after the original pipeline was designed and is not yet integrated”，写明数据截止日与排除理由，不能再说数据尚不存在。
验收标准。正文、代码注释和 DATA_SOURCES 同步；官方 dataset ID、版本/更新时间、下载查询和哈希进入 manifest；若完成验证，FloodNet 保持完全 held-out，任何阈值调节都在训练数据或预注册规则上完成。
P0-06　扩展区回归指标和旧审计文档混有过时数字
发现与证据。扩展区当前 OOF 正确值为 R² 0.335854±0.146084、MAE 0.284974±0.035757。manuscript.md §4.7 仍写 0.333±0.144、0.286±0.036；Table 3 和局限部分写 0.336，但 Table 8 仍写 0.333。report.md 与 audit.md 还保留大量 n=141、7 blocks、旧 Jaccard 0.180/0.111、旧 Moran's I 等历史段落；report.md 甚至一边写 tie-aware，一边仍写 exact top-k/H3 tie-break。
为什么重要。这些不是四舍五入差异，而是不同运行快照混用。审稿人看到同一结果有多个版本，会直接怀疑表图是否手工拼接。

验收标准。一个自动检查脚本扫描 manuscript/report/audit/README，确保每个注册 claim 只取当前 run_id；不允许现行文件中出现 n=141/7 blocks 等过期 headline；所有数值源文件均有哈希和生成脚本。

8　可直接替换进论文的英文方法文字
以下文字保持现稿的克制、方法先行写法，但把可证实边界说得更清楚。尖括号内容须由作者在重新计算后填入，不能照抄占位符。
8.1　Data provenance and 311 extraction
All source datasets are third-party public inputs; the cell-level features, labels, fitted models, predictions, diagnostics, tables, and figures are author-derived outputs. For each study profile, the archived run bundle records the official landing page, the exact download query, retrieval time, license, file size, and SHA-256 checksum. Historical 311 service requests for 2010–2014 were queried from NYC Open Data dataset 76ig-c548 using the prespecified agency, complaint-type, descriptor, date, and spatial filters reported in Supplementary Table <X>. Results were ordered by unique_key, retrieved with complete pagination, and deduplicated by unique_key before spatial assignment. No third-party derived complaint layer was used as an unverified substitute for the official extract.
8.2　Evidence target
The outcome is a screening measure of heterogeneous flood evidence rather than a calibrated flood probability or depth. DEP polygons contribute projected intersection-area fractions, whereas 311 complaints and USGS high-water marks contribute source-specific point summaries. The source columns are retained separately, and the composite is evaluated together with source-specific and threshold-sensitivity analyses. Because the sources differ in observation process, time period, and forcing, the composite is not interpreted as a single-event ground truth or a severity scale.
8.3　Spatial validation
Predictive performance was evaluated exclusively from out-of-fold predictions. H3 R9 cells were assigned to R7 spatial groups, and all descendants of a group were kept in the same fold. A buffer of <K rings / distance> around each held-out group was excluded from training, with the buffer selected before model evaluation from the residual spatial-dependence analysis. Hyperparameter and decision-threshold selection, where used, were nested within the training portion of each outer spatial fold. We report fold-wise estimates and block-bootstrap 95% confidence intervals; pooled out-of-fold metrics are secondary because scores originate from different fitted fold models.
8.4　Scale diagnostic（修复后才能使用）
Fine-resolution hotspot membership was defined on native R10 evidence scores using a fixed area budget and fractional allocation within boundary ties. For a coarse parent p, the reference membership was the area-weighted fraction of its fine-cell area assigned to the hotspot, w_ref(p)=Σ_i∈p a_i w_i / Σ_i∈p a_i. Coarse hotspots were selected under the same area budget, allowing fractional membership of the final cell or tied group. The primary overlap metric was area-weighted soft Jaccard, Σ_p a_p min(w_ref,w_coarse) / Σ_p a_p max(w_ref,w_coarse). Hard-set Jaccard was treated as a sensitivity and summarized over <1000> seeded random resolutions of tied ranks. All values shown in Table <X> and Figure <Y> were read from the same archived diagnostics table.
8.5　Reproducibility and model roles
Model evaluation and descriptive mapping used separate fitted objects. Fold-specific models produced the out-of-fold predictions used for every performance estimate. After evaluation was complete, deployment models were refitted on all cells and used only for descriptive maps and adaptive-grid screening. Each run manifest records the Git commit and dirty status, command line, configuration and input hashes, processed-table hash, feature order, fold membership hashes, software environment, model hashes, and figure/table hashes. The archived run identifier for this manuscript is <RUN_ID>.
8.6　建议替换的结果结论段
Within the two evaluated Manhattan pilot extents, spatially blocked out-of-fold predictions showed moderate ranking discrimination relative to prevalence-based references. These estimates do not establish citywide transferability, event-specific inundation probability, or hydrodynamic validity. Source-specific analyses and removal of the shoreline-distance predictor reduced, but did not eliminate, concern that shared spatial structure or reporting processes drive the observed discrimination. The current rainfall input is constant and therefore supports only a static susceptibility/evidence-screening interpretation. External validation with the now-public FloodNet event and sensor-location data is required before claims about observed event performance are made.

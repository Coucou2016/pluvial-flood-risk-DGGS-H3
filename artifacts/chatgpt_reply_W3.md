## （一）§3 Methods：结论与最小改动清单

**结论：** 总体已达到"可判断方法是否合理"的水平，但还没有完全达到 methods-type 论文的"别人只看论文即可稳定复现"的水平。其中 3.4 空间 H3-block CV 已较成熟；真正偏薄的是 3.1 H3 组装细节、3.3 模型参数、3.5 scale-loss 集合构造、3.6 adaptive screen 的预测来源、3.8 Sandy 指标定义。

### A. 已足够清楚的部分
- R7/R8/R9/R10/R11 角色基本无歧义。
- 3.4 GroupKFold 核心规则达到可复现水平（每 R9 cell → R7 parent；5 folds；同一 R7 group 不跨 train/test）。
- 3.7 PFI_h(c,r) 定义明确（Y_c、X_c、r；classifier output；无 calibration claim；constant rainfall 导致 scenario invariance）。
- 3.8 Sandy 不进入训练链写得很清楚。

### B. 审稿人最可能追问的缺口
1. **§3.1** 缺"源数据如何落到 H3 cell"的操作定义（bbox/polygon fill、point→cell、polygon area fraction、边界 cell），且未说明 area/distance 等 metric 量的 CRS 或 geodesic 方法（GIS reviewer 会问）。
2. **§3.2** feature engineering 偏薄，建议加小型 parameter/feature table（source/unit/transformation/aggregation），说明 slope 算法、D8 实现、building density 分母、distance-to-water 目标、urban flag 规则。
3. **§3.3** 模型复现缺口最大：未声明精确 sklearn class、主要 hyperparameters、logistic C/solver、是否标准化、阈值、是否调参及调参是否嵌套在训练折内。seed=42 不能替代这些。建议 Model specification table，或注明 "All unspecified parameters use scikit-learn X.Y defaults"。ponding rule 的 min–max 归一化需写明作用域（全 pilot / 训练折 / 固定物理范围）。
4. **§3.4** AP 定义需修正：sklearn `average_precision_score` 是"按 recall increment 加权的 precision 平均"，**不等于** trapezoidal PR-AUC。建议改为 "average precision (AP), computed as the recall-weighted mean of precision across score thresholds [18]"。并补 random split 的 test fraction/seed 与"fitted preprocessing 只在训练折内拟合"。
5. **§3.5** 最需要公式化："after both sets are projected onto a common support" 不足以重建 Jaccard。需明确 R10 hotspot 阈值作用域、R10 score 如何 roll up、coarse hotspot 如何再阈值、"common support" 是 R8/R9 parent 还是 expand 回 R10。建议定义 H10、聚合 A_g、coarse hotspot H_r(g)，并给 Jaccard/F1 标准公式一次。
6. **§3.6** 两个关键语义未定义：(a) screening score 是 full-fit 还是 OOF、用哪个 r；(b) "hotspot recall against uniform R11" 若 Results 未报则应删或补报；并补"R11 是否重训练/重预测"（若只比较表征应明确"no R11 model retrained"）。
7. **§3.7** 可接受，建议定义下标 h（"h denotes the H3 cell support"）。
8. **§3.8** 训练边界明确，但 diagnostic 本身不可复现：Results 里的 coastal/pluvial/overlap/coastal-only fraction/mean score difference 应在 Methods 预定义。

### C. 伪代码/公式/参数表建议
- 完整 algorithm pseudocode：不必强制。
- 参数表：价值最高（H3 roles + experiment parameters：R7 block / R8 scale-loss / R9 training / R10 fine reference / R11 adaptive；CV folds=5；hotspot quantile=0.9；refinement quantile=0.8；seed=42）。
- 公式：建议加 3 组（label target 若 §2 已有可省；scale-loss set construction + Jaccard/F1；adaptive cell-count ratio；PFI_h 已有）。

## （二）数据真实性：结论与最小改动清单

**结论：** "开放原始数据 → 下载 manifest → 本仓库计算产物 → 逐数字 audit reconciliation"的证据链已经很强，足以辩护"结果是本研究自行计算，而非从 Svellingen 等论文复制"。还需加强的是"第三方能否锁定与你完全相同的原始数据快照"。

- USGS Ida HWM 有正式 DOI `10.5066/P9OMBJPQ`；3DEP 与 NHDPlus HR 均为 USGS 公开数据产品。

### A. "自算 + 开放数据"表述是否足够
基本足够，但正文与 Data availability 应分工。正文只说原始 inputs 来源 + 所有 metrics 由本 pipeline 计算；不要在正文加入"证明没抄"的辩护语气。可在 Data/code availability 加 provenance 句："All numerical results ... are generated by the accompanying code from the documented input datasets; no numerical results from Svellingen et al. [5] are used as model outputs or evaluation results in this study."

### B. 最易被误认为"借别人结果"的数字
1. **Jaccard 0.167 vs Svellingen 0.14**：首次比较时明确一次即可，不要反复防御。
2. **PFI_h 符号**：第一处定义就写"distinct in construction and meaning from the H3-aggregated index in Svellingen et al. [5]"。
3. **synthetic 75 mm/h**：不要写 "Ida-like" 以免被误读为 Ida 实测；要么写 "synthetic 75 mm h⁻¹ scenario"，要么加一次 "a synthetic scenario label, not an observed Ida rainfall measurement"。

### C. 让 reviewer 独立核实的补强
1. Data availability 锁精确代码版本（release/tag/exact commit/Zenodo DOI），不要只写 master。
2. DOWNLOAD_MANIFEST 记录动态源（尤其 NYC 311 每日更新）的 dataset ID / API endpoint / query / retrieval timestamp / row count / SHA-256。
3. 版本化数据记录 source version（NHDPlus HR 的 VPU/release；3DEP 的 DEM product/resolution）。
4. 提供 manuscript-number → artifact mapping（指向 docs/paper/audit.md）。
5. 锁环境（Python / scikit-learn / h3 版本）。

### 最小改动优先级（8 点）
1. §3.5 补 scale-loss set construction / common-support 公式。
2. §3.3 加 model/hyperparameter 表。
3. §3.6 明确 adaptive score 是 full-fit/OOF、用哪个 r、R11 是否重拟合。
4. §3.4 改 "AP = area under PR curve"（sklearn AP 非 trapezoidal PR-AUC）。
5. §3.1/§3.2 明确 metric area/distance 的 CRS/方法。
6. §3.8 预定义 Sandy 诊断指标。
7. Data availability 写 exact tag/commit + manifest + audit mapping。
8. Manifest 对 NYC 311 等动态源保存 API query/timestamp/row count/SHA-256。
